# Context decisions

**Maintenance:** Responsible human decision owners. Agents retain proposals and actual replies on the originating request/ticket and link a human-published decision here; discovery does not create baseline decisions automatically.

No project decisions are recorded in this template. Create a dated file when a responsible owner actually clarifies or changes requirements, design, scope or a technical contract. Link the original ticket question/answer and update the canonical source as appropriate.

Use a stable decision ID and a descriptive filename. Keep owner, actual date, state, reason, alternatives, decision, affected source/criteria, applicable revision/release and consequences. Preserve superseded decisions through version control; do not silently rewrite the basis of earlier results.

For an unaccepted proposal, record Proposed. Use Accepted only after an actual decision and record the reviewer/owner's response. A context decision does not by itself authorize test execution or production release. QA review records belong with their runs and tickets.
