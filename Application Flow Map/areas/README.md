# Detailed area views

**No application areas are mapped.** Create a descriptive view only when an actual area needs more detail than the [overview](../overview.md).

Each view identifies its scope, map revision, feature/relationship IDs, sources, applicable conditions, unknowns and refresh date. Derive connections from the [canonical register](../relationship-register.md). Cross-area dependencies link to their existing IDs rather than invent duplicate features. Keep runtime loops, failures and alternative paths readable; provide the source record for details that do not fit the diagram.

An area view or helper snapshot is a bounded projection, not evidence of whole-application completeness. List omitted boundary connections. Preserve previous versions and refresh affected views after canonical changes.
